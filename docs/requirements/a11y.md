# Accessibility issues, deliberate (/a11y)

Purpose: a known-bad page for accessibility checks, with each violation listed next to its WCAG success criterion, and a switch to the fixed version for before/after comparisons.

## User stories
- As an accessibility tester I scan the page and find the documented violations.
- As a tester I switch to the fixed version and confirm the violations are gone.

## Acceptance criteria
- In broken mode the demo form contains: an email input with only a placeholder (1.3.1 / 3.3.2), low-contrast text (1.4.3), an image without alt (1.1.1), an icon-only button with no accessible name (4.1.2), a heading jump h2 → h5 (1.3.1), positive tabindex values (2.4.3) and a French passage without lang (3.1.2).
- The violations table lists all 7 with status "Present"; "Violations present" shows 7 and state.violations = 7, state.mode = "broken".
- When I turn on "Show fixed version", then state.mode = "fixed", state.violations = 0, the input has the label "Email address", the button is named "Search", the image has alt text, headings are h2 → h3, tabindex is removed and the passage has lang="fr".
- Typing in the email field sets state.email in both modes; clicking the icon button increments state.iconClicks.

## Trap params
variant=b ("Show accessible version", reversed table order), unstableIds.
